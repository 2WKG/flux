## Top 3 remaining risks

1. **Nothing hit the Anthropic API live.** Model ids (`claude-opus-5`, `claude-sonnet-5`) and the Opus 5 400-rules (temperature/prefill) rest on the `claude-api` skill table (cached 2026-06-24), not `models.retrieve`. First thing the copilot lane must run with a real key: `client.models.retrieve(COPILOT_MODEL)` and one streamed `strict`-tool call, and wire the `/health` guard the spec now requires.
2. **Dependency gaps the specs assumed were present.** Python: `pydantic-settings`, `voyageai` missing; `anthropic>=0.40` pin admits the pre-1.0 API. Web: `@deck.gl/extensions`, `react-markdown`, `tailwindcss`, `lucide-react`, `@protomaps/basemaps`, `pmtiles` missing; no `typecheck`/`lint` scripts. Each is a Saturday-morning `add`, but any one of them unblocked late will eat demo time.
3. **`read_only=True` does not stop `COPY … TO` file writes** (verified on duckdb 1.5.5). The `sql` tool's denylist is now the only thing between the model and the filesystem; the mutation probe 15(b) in spec 05 must actually be run, not just listed.
