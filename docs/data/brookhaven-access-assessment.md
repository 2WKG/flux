# Brookhaven data — access assessment

**Outcome: UNAVAILABLE as a dataset. AVAILABLE as open-source tooling that generates data.**

Brookhaven National Laboratory does not publish a downloadable power-grid dataset that this
project could ingest. The Brookhaven work referenced in the meeting is a *modelling programme*,
not a data release. Its open-source surface is a data **generator**, and the grid data it was
validated against is proprietary utility SCADA held under restricted governance.

Nothing in this assessment assumes access. Every claim below is sourced.

---

## 1. What "Brookhaven data" actually refers to

Three distinct things travel under this name. Only the third has any public artifact.

### 1a. GridFM — Genesis Mission Phase II

- BNL leads a three-year, **$14.2M** DOE Genesis Mission Phase II award ($3.9M to Brookhaven),
  PI **Hendrik Hamann**, to build a grid foundation model targeting ~1 billion grid scenarios
  simulated per day.
- Over 150 collaborators: MIT, IBM, NVIDIA, Microsoft, AWS, and utilities including National
  Grid, Con Edison and Alabama Power.
- **Announced 2026-09-01 — four days before this assessment.** A three-year effort at day four.
- Open-source development is administered in partnership with **Linux Foundation Energy**.
- The announcement names **no dataset release**.

### 1b. GridSearch — BNL + AWS

- Announced June–July 2026. Applies GridFM to accelerate interconnection studies for AI data
  centres; claimed 20–100× (elsewhere up to 1,000×) speedups.
- Validated on a **real transmission topology: a full year of Hydro-Québec SCADA across a
  1,200-bus network**.
- That data was used **"under strict data governance and security safeguards."** It is utility
  operational data. **Treat as not obtainable.** Do not plan around it.

### 1c. OpenGridFM — the open-source layer (the only reachable artifact)

Governed under LF Energy. Two components are public today:

| Component | What it is | License | Ships data? |
|---|---|---|---|
| `gridfm-datakit` | Generates PF/OPF datasets by perturbing loads, dispatch, topology and branch parameters | **Apache-2.0** | **No** — generator only |
| `gridfm-graphkit` | Companion library, published on PyPI | (not verified) | No |

A large synthetic dataset generated by `gridfm-datakit` is **planned** for release on Hugging
Face. As of 2026-09-05 it is announced intent, not a downloadable artifact. Do not schedule
against it.

## 2. Access path

There is no dataset access path to record, because there is no dataset. The tooling path is:

```
pip install gridfm-datakit
gridfm_datakit setup_pm          # installs the Julia side
```

Input grids it accepts: MATPOWER `.m` files, PGLib cases, or a custom grid file. Documented
ceiling is ~30,000 buses for power flow and ~10,000 for OPF. Output is Parquet, written locally.

**This means: even in the best case, using it would mean feeding it our own ACTIVSg2000 case and
generating synthetic samples — not receiving Brookhaven data.** That is a different activity
from what the issue title implies, and it duplicates capability we already have in pandapower.

---

## 3. Feasibility blocker on this machine

`gridfm-datakit` requires:

- **Python 3.10, 3.11 or 3.12**, and per its own documentation **Windows cannot use 3.12**.
- **Julia**, with **PowerModels** and **Ipopt**.

This project pins `requires-python = ">=3.12,<3.13"` in `pyproject.toml`, and the primary
development machine is Windows 11.

**Those two constraints do not intersect.** On Windows, the tool needs ≤3.11; the project
requires exactly 3.12. Adopting it would mean either a second Python environment or a Julia
toolchain install, plus a solver stack — against a 48-hour clock.

> Confidence note: the Windows/3.12 exclusion is taken from the project's own documentation and
> has **not** been reproduced locally. Verify before relying on it either way. The Julia
> dependency is unambiguous and is on its own sufficient to make this a poor weekend bet.

## 4. Coverage

| Dimension | Finding |
|---|---|
| Geographic | Not applicable — no dataset. Generated data inherits the geography of whatever case you feed it. |
| Temporal | Not applicable. `gridfm-datakit` produces perturbation samples, not time series. |
| Real Brookhaven-adjacent operational data | Hydro-Québec, 1,200 buses, one year of SCADA — **Quebec, not Texas, and not obtainable.** |

For the current Texas demo this is a coverage mismatch even if access existed.

---

## 5. Quality and schema caveats

- Data produced by `gridfm-datakit` is **synthetic by construction** — perturbations around a
  base case. It carries the same "synthetic, label it as such" obligation as ACTIVSg2000, with
  an extra layer: the perturbations are also synthetic.
- Schema is the tool's Parquet output, determined by our own configuration. There is no external
  schema to conform to, and therefore no schema-compatibility work to do.
- The 1,000× speedup figures are vendor/lab claims from announcements, not independently
  reproduced here. Do not repeat them in the pitch.

---

## 6. Recommendation

**Do not pursue Brookhaven data for the hackathon.** Record it as evaluated and unavailable.

Reasons, in order of weight:

1. There is no dataset to obtain — the ask does not have an object.
2. The one real grid dataset in the programme is restricted utility SCADA for Quebec.
3. The open-source tool is a generator whose function pandapower already covers for our needs.
4. Its toolchain conflicts with our pinned Python on Windows and adds a Julia dependency.
5. The programme is four days old. Public artifacts should be re-checked in months, not hours.

**Adjacent source that *is* downloadable:** `microsoft/GridSFM_US_power_grid` on Hugging Face —
geographically grounded, built entirely from public data, 48 states, intended for AC-OPF work;
`GridSFM_Open` (~15M parameters) is MIT-licensed. This falls under **2WKG-135** (Assess Texas A&M
and Microsoft GridSFM source compatibility), not this issue. Flagged here so it is not lost.

**Re-check trigger:** if the LF Energy Hugging Face dataset is actually published, this
assessment is stale. Nothing else about the programme changes the answer before then.
